Cantus — one socket, always a path.

A realtime voice standard that replaces SIP, SDP and RTP with a single 5-tuple, typed negotiation, and traversal that is on from the first packet. A call either connects and you hear it, or it tells you why not — there is no third outcome.

Why Cantus

Each answer is normative in the standard, not a policy in a config file.

"It connected, but nobody can hear anything."

Impossible by construction: signalling and media share one 5-tuple, so one NAT mapping serves the call and the two address views cannot disagree.

Traversal is six knobs you must reconcile.

Reach is always on. The relay mapping opens at startup with registration, so the fallback exists before anyone dials — and ice_support=no is not a default here.

A call should not open 10,000 UDP ports.

One port carries everything. There is no port range to open, no second address to rewrite, and nothing to keep aligned in a firewall.

SDP negotiation is 2,580 lines of glue.

Capability sets are ordered data: one round trip, caller's order wins, no re-offer, no UPDATE, no PRACK.

Every path decision is invisible.

Direct, relay, failover and recovery are events with timings. The suite asserts them, and cantus demo prints them.

You have to trust the From header.

Identity is a key: every signed message proves the node, not the field it typed in.

The pieces

A standard, a reference stack that proves it, and the suite that keeps it honest.

The standard

Wire format, handshake, negotiation, call machine, Reach, media, identity, routing, reason codes, conformance suite. Normative, and small enough to read in one sitting.

The reference stack

Perl 5, core modules only. Real UDP sockets, a real relay, a real NAT middlebox in the test path. It runs anywhere Perl runs, including this machine.

The conformance suite

167 assertions: audio verified by amplitude, ACTIVE read from the state machine, NAT drops counted inside the middlebox.
